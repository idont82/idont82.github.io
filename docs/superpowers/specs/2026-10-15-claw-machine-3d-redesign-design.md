# 인형뽑기 게임 3D 전면 재설계 설계

## 배경

Search Console 실측(2026-07-13 ~ 10-12)에서 `idont82.github.io` 전체 클릭 3,230건 중 2,997건(92.8%)이 `claw-machine.html`과 `claw-machine-guide.html`에서 나왔다. 나머지 25개 페이지의 제휴 글은 3개월 합계 72클릭에 그친다. 사이트의 유일한 트래픽 자산은 인형뽑기이며, 검색어 상위 10개도 전부 "인형뽑기 게임" 계열이다.

반면 게임 페이지의 수익화는 상품명도 가격도 없는 쿠팡 배너 이미지 3장이 전부고, 모든 제휴 링크에 subId가 없어 어느 페이지가 수익을 냈는지 측정할 수 없다. 과거 최다 전환 상품이 "레빗 미니 인형뽑기"(91클릭)인 것으로 보아 게임 방문자의 구매 의향 자체는 존재한다.

이 설계는 게임의 3D 비주얼을 사진 기반 모델로 교체하면서, 동시에 기계 안의 인형을 실제 판매 상품과 1:1로 연결해 게임과 수익을 잇는다.

## 목표

인형 16개와 기계를 사진 기반 GLB 모델로 교체한다. 기계 안에 보이는 인형이 곧 쿠팡에서 파는 그 상품이 되게 하고, 뽑은 인형에서 해당 상품 링크로 이어지게 한다. 교체 과정의 어느 단계에서도 현재 월 1,000클릭 규모의 게임 페이지가 느려지거나 동작을 멈추지 않아야 한다.

## 범위

게임의 유한상태기계, 진자 물리, 집기 확률, 조작계(조이스틱·터치·키보드), localStorage 수집함 스키마, 페이지 URL과 문서 구조는 바꾸지 않는다. 검색 순위가 걸린 자산이므로 `claw-machine.html`의 제목, 메타 태그, 본문 텍스트는 유지한다.

교체 대상은 `claw-machine.js`의 캐릭터 생성부(약 432~1,270줄)와 기계 구조물 생성부, 조명과 재질, 수집함 썸네일 생성기다.

## 인형 소스와 권리

현재 `PLUSHIE_THEMES`에는 짱구·짱아·맹구, 시나모롤, 한교동, 도라에몽, 뽀로로·루피 등 타사 보유 캐릭터가 포함되어 있다. 이 캐릭터들의 입체 형상을 새로 제작하면 2차적저작물 복제에 해당하고, 수익화 중인 사이트이므로 권리자 요구 시 GitHub Pages DMCA로 사이트 전체가 내려갈 수 있다.

따라서 캐릭터 형상의 출처를 **쿠팡에서 판매 중인 해당 IP 정품 봉제인형 상품 이미지**로 한정한다. 상품 이미지는 쿠팡 파트너스 활동으로 그 상품을 홍보하는 목적에 쓰이며, 게임 안의 인형은 그 상품의 표현이 된다. 캐릭터를 새로 그려 3D화하는 경로는 쓰지 않는다. 생성형 이미지 모델이 유명 캐릭터 생성을 거부하므로 실무적으로도 불가능하다.

상품을 찾지 못한 캐릭터는 교체하지 않고 기존 procedural 모델을 유지한다.

## 에셋 파이프라인

에셋 제작은 오프라인 1회성 작업이며 게임 런타임과 분리된다. `scripts/assets/build-plushie.js`가 테마 단위로 다음을 수행한다.

쿠팡 검색 API로 해당 캐릭터의 정품 봉제인형 상품을 조회해 상품명, 가격, 로켓배송 여부, 상품 이미지 URL을 얻는다. 상품 이미지를 `assets/src/<theme>/<char>.png`로 내려받는다. 사내 GPU 서버 gpu3d에 `POST /jobs`로 `kind=prop`, `polycount=8000`, `heightM=0.3`을 주어 작업을 만들고, `GET /jobs/{id}`를 폴링한 뒤 `GET /jobs/{id}/result`로 GLB를 받는다. 받은 GLB를 Draco 메시 압축과 512px WebP 텍스처로 줄이고, 160px 썸네일 PNG를 굽는다. 결과를 `assets/models/<theme>/<char>.glb`와 `<char>.webp`로 저장하고 테마 매니페스트를 갱신한다.

gpu3d의 주소와 토큰은 `gpu3d/api.txt`에서 읽으며 이 파일은 `.gitignore`에 추가한다. 사내 서버 주소와 토큰은 어느 커밋 대상 파일에도 적지 않는다. 게임은 커밋된 GLB만 읽으므로 런타임에 사내망 의존이 없다.

기계 모델도 같은 경로로 만든다. 실제 인형뽑기 기계 사진을 소스로 `kind=prop`, 높은 polycount로 한 번 생성한 뒤 수동 정리한다.

## 매니페스트

테마마다 `assets/models/<theme>/manifest.json`을 둔다. 각 항목은 캐릭터 키, 모델 경로, 썸네일 경로, 상품명, 가격, 가격 기준일, 로켓배송 여부, 딥링크 URL을 담는다. 딥링크는 쿠팡 딥링크 API로 발급하며 `subId=clawgame`을 포함한다.

매니페스트는 게임의 상품 카드, 수집함, 뽑기 성공 화면이 공유하는 단일 출처다. 상품이 단종되거나 가격이 바뀌면 파이프라인을 다시 돌려 매니페스트만 갱신한다.

## 로딩 전략

게임은 모델 로딩을 기다리지 않는다. 기존 procedural 캐릭터로 즉시 시작하고, GLB가 도착하는 대로 해당 인형의 메시만 교체한다. 매니페스트나 GLB 요청이 실패하면 경고 없이 procedural 상태를 유지한다. procedural 생성 코드는 fallback으로 남긴다.

모델은 현재 선택된 테마만 받는다. 테마를 바꾸면 그때 해당 테마를 받고, 한 번 받은 테마는 캐시한다. 기계 모델과 환경맵은 페이지 진입 시 한 번 받는다.

Three.js 0.162의 `GLTFLoader`와 `DRACOLoader`를 importmap에 CDN으로 추가한다. 빌드 단계는 도입하지 않는다.

메시를 교체할 때 `userData`의 `type`, `char`, `theme`, `radius`와 바운딩 반경, 그룹의 원점 기준을 기존 값 그대로 유지한다. 물리와 충돌 코드는 수정하지 않는다. 모델의 바운딩 박스를 `plushieScale`에 맞춰 정규화한 뒤 그룹에 넣는다.

## 기계와 조명

기계는 GLB 한 개로 교체한다. 유리면은 `MeshPhysicalMaterial`의 transmission으로 표현하고, 프레임·LED·경품구는 모델에 포함한다. 조명은 상단 스포트라이트와 256px RGBE 환경맵 하나로 구성한다.

큰 인형 모드(`isLargeMode`)의 기계 크기 전환 동작은 유지한다.

## 수익 연결

뽑기에 성공하면 세션당 첫 1회에 한해 방금 뽑은 인형의 상품 카드를 띄운다. 카드는 썸네일, 상품명, 가격과 기준일, 로켓배송 표시, 쿠팡 링크 버튼으로 구성한다. 같은 세션의 이후 성공에서는 띄우지 않는다. `sessionStorage`로 판단한다.

COIN 버튼의 광고 푸터는 배너 이미지 3장을 현재 테마의 상품 카드 3개로 바꾼다. 수집함은 각 인형 아래에 가격과 링크를 표시한다.

모든 쿠팡 링크에 `subId=clawgame`을 붙인다. iframe 캐러셀 위젯은 `subId=clawwidget`을 쓴다. `assets/coupang-tracking.js`는 수정하지 않고 `data-coupang-placement` 속성만 카드에 부여해 기존 GA 추적을 유지한다.

쿠팡 파트너스 고지 문구는 현재 위치와 문구를 그대로 둔다.

## 용량 예산

저장소는 이미 `.git` 605MB, `images` 129MB다. 에셋 추가는 다음 예산을 넘지 않는다.

기계 GLB 2.0MB, 환경맵 0.1MB, 인형 1개 0.3MB, 테마 1개 최대 1.8MB(dino 6개 기준), 인형 16개 전체 4.8MB. 첫 화면이 받는 양은 기계와 환경맵 2.1MB에 테마 하나를 더한 값이다.

예산을 넘기면 polycount와 텍스처 해상도를 낮춰 맞춘다. 예산 준수는 각 테마의 합격 기준이다.

## 롤아웃

`dino` 테마를 먼저 한다. 공룡은 타사 IP가 아니므로 파이프라인 품질과 용량만 검증하면 된다. dino가 합격하면 나머지 6개 테마를 하나씩 올린다. 각 테마는 독립적으로 배포 가능하며, 문제가 생기면 해당 테마의 매니페스트만 제거해 procedural로 되돌린다.

## 검증

각 테마마다 `node server.js`로 `localhost:3000/claw-machine.html`을 띄워 확인한다. 페이지 진입 직후 모델 로딩 완료 전에도 게임이 시작되고 조작되는지, GLB 교체 후 집기와 떨어뜨리기와 경품구 판정이 그대로 동작하는지, 네트워크를 끊은 상태에서도 procedural로 정상 동작하는지, 추가된 에셋 총량이 예산 이내인지, 뽑기 성공 카드와 COIN 푸터와 수집함의 모든 쿠팡 링크에 `subId=clawgame`이 붙어 있는지, 기존 배너 이미지 참조가 남아 있지 않은지를 검사한다.

검증에 실패하면 성공으로 보고하지 않고 원인을 확인한다. 사용자의 다른 미커밋 파일은 수정하거나 스테이징하지 않는다.
