# Facebook 카드뉴스 자동화 설계

## 목표

기존 블로그 콘텐츠와 쿠팡 상품 데이터를 활용해 Facebook 페이지에 카드뉴스를 자동 발행한다. 최우선 성과는 팔로워 수나 단순 도달이 아니라 쿠팡 파트너스 수익이다. 초기 2주 동안 블로그 경유 게시물과 쿠팡 직접 연결 게시물의 도달당 수익을 비교해 이후 운영 비중을 결정한다.

## 범위

이번 작업은 다음을 포함한다.

- 기존 블로그와 상품 JSON에서 발행 후보를 구성한다.
- 1080×1350 PNG 카드뉴스를 생성한다.
- Facebook Graph API로 Facebook 페이지에 게시한다.
- 예약 실행, 재시도, 중복 방지 및 발행 상태 기록을 제공한다.
- Meta 성과, 사이트 유입, 쿠팡 클릭을 게시물 단위로 연결한다.
- 별도 테스트 페이지와 자동 테스트로 실제 발행 전 동작을 검증한다.

다음은 이번 범위에 포함하지 않는다.

- Instagram 자동 발행
- Facebook 광고 캠페인 자동 운영
- 새로운 블로그 글이나 상품 추천문을 생성형 AI로 자동 작성하는 기능
- 공개 API가 확인되지 않은 쿠팡 파트너스 주문·수익 보고서의 비공식 수집

## 운영 원칙

- Facebook을 첫 번째 자동 발행 채널로 사용한다.
- 일반 카드뉴스의 약 80%는 블로그 구매 가이드로 연결한다. 초기 14건에서는 11건을 배정한다.
- 단일 상품이나 명확한 특가 성격의 게시물 약 20%는 쿠팡으로 직접 연결한다. 초기 14건에서는 3건을 배정한다.
- 모든 게시물 본문과 마지막 카드에 쿠팡 파트너스 수수료 고지를 넣는다.
- 같은 주제나 상품은 60일 이내에 반복 발행하지 않는다.
- 첫 2주는 매일 오후 8시 30분(Asia/Seoul)에 한 건씩 발행한다. 시간은 설정값으로 변경할 수 있다.

## 콘텐츠 구성

첫 2주에는 한 주제에 집중하지 않고 다음 범주를 순환한다.

- 연예인 착장
- 아이돌 굿즈
- 계절 생활용품
- 불만·문제 해결형 상품
- 인형뽑기·취미 상품

기본 카드뉴스는 다섯 장으로 구성한다.

1. 시선을 끄는 질문이나 문제
2. 구매 전에 놓치기 쉬운 점
3. 핵심 선택 기준
4. 대상별 추천 또는 비교
5. 클릭 유도 문구와 제휴 고지

직접 연결 게시물은 내용에 따라 세 장까지 줄일 수 있지만, 표지와 제휴 고지 카드는 항상 포함한다.

## 시스템 구조

자동화는 기존 저장소의 Node.js 및 Python 스크립트 패턴을 따른다. 별도 상시 서버 대신 GitHub Actions의 예약 작업을 사용한다.

```text
블로그 HTML·상품 JSON
        ↓
발행 후보 선정 및 큐 검증
        ↓
Python/Pillow 카드뉴스 생성
        ↓
본문·링크·제휴 고지 조합
        ↓
Facebook Graph API 발행
        ↓
게시 결과 및 성과 기록
```

### 구성 요소

`data/facebook-post-queue.json`

- 게시물 ID, 범주, 원문, 연결 방식, 예약 시각, 상태를 저장한다.
- 직접 연결 게시물에는 쿠팡 파트너스 URL 또는 이를 만들 수 있는 상품 식별자를 포함한다.
- 발행된 게시물에는 Facebook 게시물 ID와 영구 링크를 기록한다.

`scripts/generate-facebook-cards.py`

- 기존 Python/Pillow 이미지 생성 방식을 확장한다.
- 큐 항목과 블로그 메타데이터를 입력받아 카드 PNG를 만든다.
- 지정된 한글 글꼴, 안전 여백, 줄 수 제한을 적용한다.

`scripts/publish-facebook-posts.js`

- 발행 시각이 지난 `queued` 항목 한 건을 선택한다.
- 카드 파일, 본문, 링크 및 고지를 검증한 뒤 Graph API에 게시한다.
- 성공 결과를 큐에 기록하며 재실행 전에 중복 여부를 확인한다.

`scripts/collect-facebook-insights.js`

- 게시물 ID를 기준으로 Meta에서 제공하는 도달과 반응 지표를 수집한다.
- 지표 이름이나 가용성이 API 버전에 따라 달라질 수 있으므로 지원되는 항목만 저장하고 누락을 오류로 취급하지 않는다.

GitHub Actions

- 수동 실행과 매일 예약 실행을 모두 제공한다.
- 동시 실행을 한 건으로 제한한다.
- 카드 생성, 검증, 발행, 결과 기록을 순서대로 실행한다.
- Meta 토큰과 쿠팡 키는 GitHub Secrets에서 읽으며 로그에 출력하지 않는다.

## 큐 데이터 모델

최소 큐 항목은 다음 형태를 사용한다.

```json
{
  "id": "20260806-seasonal-01",
  "category": "seasonal",
  "article": "/blog/example.html",
  "linkMode": "blog",
  "scheduledAt": "2026-08-06T20:30:00+09:00",
  "status": "queued",
  "attempts": 0,
  "facebookPostId": null,
  "facebookPermalink": null
}
```

상태 값은 다음과 같다.

- `queued`: 발행 대기
- `rendered`: 카드 생성 및 정적 검증 완료
- `publishing`: API 발행 진행 중
- `published`: Facebook 게시물 ID까지 기록 완료
- `failed`: 자동 재시도 한도를 넘겼거나 사람의 조치가 필요함

## 링크와 추적

### 블로그 경유

Facebook 본문에 다음 UTM 형식의 블로그 URL을 넣는다.

```text
?utm_source=facebook&utm_medium=social&utm_campaign=card_news&utm_content=<post-id>
```

블로그의 기존 `coupang_click` 이벤트가 페이지 경로, 배치 위치 및 상품 유형을 기록한다. 따라서 게시물별 Facebook 유입과 블로그 내 쿠팡 클릭을 연결할 수 있다.

### 쿠팡 직접 연결

직접 링크의 `subid`에는 게시물 ID를 안전한 길이와 문자 집합으로 변환해 넣는다. 원본 게시물 ID와 실제 `subid`의 매핑을 큐 또는 결과 파일에 함께 저장한다.

### 링크 변경

블로그 경유 방식은 상품 품절이나 추천 변경 시 블로그만 수정한다. Facebook의 과거 게시물 URL은 유지한다. 직접 연결 게시물은 게시 전에 링크 유효성을 확인하고, 이미 발행된 링크가 만료되면 새 게시물을 만들지 여부를 사람이 결정한다.

## 발행 흐름

1. 발행 시각이 지난 `queued` 항목을 한 건 선택한다.
2. 60일 중복 규칙과 80:20 목표 비율을 확인한다.
3. 블로그 URL, 상품 데이터, 이미지 및 제휴 고지를 검증한다.
4. 카드 이미지를 생성하고 크기, 파일 형식, 텍스트 영역을 확인한다.
5. 상태를 `rendered`, 이어서 `publishing`으로 변경한다.
6. 최근 Facebook 게시물을 조회해 동일한 UTM `utm_content` 또는 쿠팡 `subid`가 있는지 확인한다.
7. 중복이 없으면 Graph API로 미디어와 본문을 게시한다.
8. Facebook 게시물 ID와 영구 링크를 기록하고 `published`로 변경한다.
9. 결과 파일 변경만 커밋한다. 사용자 작업 등 관련 없는 저장소 변경은 포함하지 않는다.

## 중복 방지와 복구

API 성공 직후 작업이 중단되면 로컬 상태만으로는 성공 여부를 판단할 수 없다. 재실행 시 Facebook 최근 게시물에서 게시물 고유 식별자가 포함된 링크를 먼저 찾는다. 이미 존재하면 새로 게시하지 않고 해당 게시물 ID를 큐에 복구한다.

오류별 처리는 다음과 같다.

- 네트워크 오류, HTTP 429, Meta 5xx: 지수 백오프로 최대 세 번 재시도
- 이미지, 본문 또는 링크 검증 오류: API를 호출하지 않고 `failed` 처리
- 토큰 만료 또는 권한 부족: 자동 재시도하지 않고 작업 실패 알림
- 일부 미디어만 업로드됨: 최종 게시를 중단하고 가능한 범위에서 임시 미디어 정리
- 큐 결과 커밋 충돌: 게시물 중복 조회 후 최신 큐에 결과를 다시 반영

실패한 항목을 건너뛰어 다음 항목을 자동 발행하지 않는다. 콘텐츠 순서와 80:20 실험 배정이 의도치 않게 바뀌는 것을 막기 위해 사람의 확인 후 재개한다.

## 보안

- Page Access Token과 쿠팡 API 키는 GitHub Secrets에만 저장한다.
- 토큰, 서명, 원본 API 응답의 민감 필드는 로그에 남기지 않는다.
- 워크플로 권한은 큐 결과를 기록하는 데 필요한 저장소 쓰기로 제한한다.
- Facebook 페이지, Meta 앱 및 테스트 페이지의 관리자 권한은 최소 인원에게만 부여한다.
- 외부 기여 코드가 비밀 값에 접근하지 못하도록 예약 및 수동 워크플로의 실행 조건을 제한한다.

## 성과 측정

첫 2주에는 게시물별로 다음 흐름을 측정한다.

```text
Facebook 도달 → 링크 클릭 → 블로그 방문 → 쿠팡 클릭 → 주문·수익
```

수집 위치는 다음과 같다.

- Meta Insights API: API가 제공하는 게시물 도달 및 반응 지표
- 사이트 GTM: UTM 방문과 `coupang_click` 이벤트
- 쿠팡 파트너스: 게시물별 `subid` 기준 주문 및 수익

핵심 비교 지표는 게시물 1,000회 도달당 쿠팡 파트너스 수익이다. 보조 지표로 블로그 방문률, 블로그 방문 대비 쿠팡 클릭률, 반응률을 사용한다. 조회수나 반응률만으로 블로그 경유와 직접 연결 중 승자를 결정하지 않는다.

쿠팡의 공개 개발자 문서는 판매자용 API를 중심으로 제공된다. 파트너스 주문·수익 보고서 API 접근이 해당 계정에 제공되는지는 구현 전에 확인한다. 접근할 수 없다면 발행과 클릭 수집은 자동화하되 최종 주문·수익은 파트너스 포털 보고서로 대조한다. 비공식 스크래핑이나 브라우저 자동화로 이를 우회하지 않는다.

## 테스트

### 자동 테스트

- 큐 JSON 스키마와 상태 전이 검증
- 초기 14개 게시물의 블로그 11건, 직접 연결 3건 배정 검증
- 범주 순환과 60일 중복 금지 검증
- 모든 게시물의 제휴 고지, UTM 및 `subid` 검증
- 카드 이미지의 1080×1350 크기, PNG 형식, 안전 여백 검증
- 한글 글꼴 누락, 최대 줄 수 초과 및 텍스트 영역 이탈 검증
- Meta API 성공, 일시 오류, 영구 오류 및 재시도 모의 테스트
- API 성공 후 상태 기록 실패 상황의 중복 방지 테스트
- 비밀 값이 로그나 결과 파일에 포함되지 않는지 검사

### 실제 연동 검증

1. GitHub Actions의 `dry-run`으로 카드와 본문만 생성한다.
2. 별도 Facebook 테스트 페이지에 한 건을 실제 게시한다.
3. 게시물 이미지 순서, 한글, 링크, 고지 및 모바일 표시를 확인한다.
4. 블로그 UTM 방문과 `coupang_click` 이벤트 수집을 확인한다.
5. 동일 작업을 재실행해 중복 게시가 발생하지 않는지 확인한다.
6. 수동 워크플로가 안정적으로 통과한 뒤 예약 실행을 활성화한다.

## 초기 성공 기준

- 테스트 페이지에서 생성, 게시, 결과 기록 및 중복 방지가 모두 성공한다.
- 첫 14개 게시물에 누락된 링크나 제휴 고지가 없다.
- 첫 14개 게시물이 모두 정상 발행되고 중복 게시가 없다.
- 정규 운영 전환 후 최근 30개 게시물 기준 자동 발행 성공률이 95% 이상이다.
- 모든 블로그 경유 게시물에서 UTM 방문과 쿠팡 클릭 이벤트를 구분할 수 있다.
- 직접 연결 게시물의 `subid`를 원본 게시물 ID로 역추적할 수 있다.
- 2주 종료 시 블로그 경유와 직접 연결의 도달당 수익을 비교할 수 있다. 파트너스 수익 API가 없으면 포털 보고서를 사용한 대조 결과를 포함한다.

## 구현 전 필요한 수동 설정

다음 초기 설정은 API로 대체하지 않는다.

- Facebook 페이지 생성
- Meta 개발자 앱 생성
- Facebook Login과 Pages API 권한 구성
- 최초 OAuth 로그인과 권한 동의
- Page Access Token 발급 및 GitHub Secrets 등록
- 별도 Facebook 테스트 페이지 준비

초기 설정 이후 카드 생성, 예약 발행, 재시도, 결과 기록과 가능한 범위의 성과 수집은 API와 예약 작업으로 자동화한다.
